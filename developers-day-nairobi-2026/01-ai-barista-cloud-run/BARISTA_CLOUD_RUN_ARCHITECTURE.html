01Workshop overview

Build a coffee shop assistant that recommends menu items, answers price questions, and responds to preferences using menu facts. The core lab reads eight records from a local JSON file. The optional extension adds semantic retrieval from Firestore.

Core lab · Local retrieval

Streamlit + Google ADK + Gemini + Cloud Run. The menu tool returns all eight menu records for a menu lookup.

Extension · Vector retrieval

Firestore stores menu records and embeddings. A query returns up to three candidates using cosine distance.

Workshop scope. These diagrams describe the supplied lab implementation. Rehearsal observations come from the source guide; this document does not establish a new deployment or runtime verification.

02Serverless agent architecture

app.py owns the browser interface, sidebar, session ID, and runner. agent.py defines barista_agent and get_menu(). ADK executes the Python tool when Gemini requests it.

The sidebar reads the menu separately from the chat tool. A populated sidebar confirms its read path; a correct recommendation tests the agent path.

03Chat and tool-call sequence

Example: “Recommend something strong and warm.” The expected recommendation is Espresso Solo, described as a single shot in the menu.

A greeting may skip tool execution. Session history lives in memory and can reset on refresh or a new connection. Continue follow-up questions in the same chat session.

05Firestore vector retrieval

The chat endpoint uses global; embeddings use us-central1 in the supplied guide. Seed writes and queries must use the same embedding model, database, and vector length. Changing models requires re-embedding the stored documents.

Retrieval behavior. Similarity ranks candidates. Verify dietary preferences against explicit tags and listed allergens. Top-three retrieval can miss an item, so an exhaustive availability check needs an exact lookup.

Live Matcha update

  1. Ask about matcha before insertion in a fresh vector-service session.
  2. Run python seed.py --matcha in the configured vector folder.
  3. Confirm direct search returns Matcha Green Tea Latte.
  4. Refresh the app and verify the sidebar and chat show the listed $5.50 price.

The database update is visible to subsequent reads without redeploying Cloud Run. The base service retains its original local menu.

06Build and deployment path

Use the same Cloud Shell terminal so exported variables and the deploy_barista function remain available. The source build creates a container image in Artifact Registry, then deploys a Cloud Run revision.

Deployer and builder

The signed-in identity starts deployment and needs permission to act as the selected runtime account. Cloud Build uses its build identity to produce the image.

Runtime identity

The dedicated account receives the guide's Vertex AI role. The vector extension adds Firestore read access; the seeding identity needs write access.

Follow the complete commands in step 6. A Service URL and a healthy revision are followed by browser and chat checks.

09Resource lifecycle

  1. Inventory the selected track's services, database, identity, and revision images.
  2. Remove its Cloud Run services after the workshop.
  3. Remove added IAM bindings and the dedicated runtime identity once no services use it.
  4. Remove the named Firestore database only if it was created for this lab and its data can be discarded.
  5. Review image digests and source archives; remove only confirmed workshop artifacts.

The source guide uses a project that also contains other work. Preserve shared resources and follow the individual resource commands in step 9. Review billing usage after cleanup.
