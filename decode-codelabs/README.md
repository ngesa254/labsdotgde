# From Code to Cash

Building Agentic Payment Systems with M-Pesa, Apigee, and Google Cloud — guided DECODE codelab edition by **Ngesa Marvin**.

The generated landing page is [site/index.html](site/index.html). Lab 1 has 11 guided steps (97 estimated minutes); Lab 2 has 9 (79 minutes). Allow additional time for account setup, permissions and provisioning. These are estimates, not an event schedule.

The core builds catalog, basket and payment preparation tools, then an ADK agent using a protected MCP endpoint. Payment initiation is disabled by default; callback reception, reconciliation, durable orders and an Apigee proxy are not implemented. The optional sandbox initiation function is supplied and tested using mocked HTTP only. Read [SOURCE_AUDIT.md](SOURCE_AUDIT.md) before presenting payment or security claims.

## Preview the generated site

From this folder:

```bash
python3 scripts/preview.py
```

Open **http://127.0.0.1:8765/** and keep the command running. It serves `site/` through HTTP; opening the files directly is not the supported preview. If the port is occupied, the script selects a free port and prints the actual URL. Ctrl-C stops this preview only.

To reproduce the tested subdirectory mount:

```bash
python3 scripts/preview.py --prefix /workshop/
```

Open **http://127.0.0.1:8765/workshop/** (or the printed port). This is a local URL, not a public deployment. The authoring session checked that URL with a real browser. Start the server again for a new session.

The landing page and guided labs serve their runtime assets locally. The official codelab scripts, styles and fonts are included under `site/vendor/claat/`, with checksums and upstream license notices. Navigation is browser-tested with external requests blocked; cloud exercises, installation and reference links still need internet access. See [TOOLCHAIN.md](TOOLCHAIN.md) for asset provenance and maintenance.

## Build and validate

Build prerequisites: Python 3.11+ for scripts, plus the pinned claat executable. No Go, Node.js or Docker is required on the tested macOS host. The sample application runtime is Python 3.11.

```bash
cd "/Users/ngesamarvine/Documents/Terminal F/labsdotgde/decode-codelabs"
python3 scripts/install_claat.py
python3 scripts/build.py
```

The installer downloads the exact tested official macOS binary into `.tools/`, verifies SHA-256, and needs network permission on a fresh checkout. It does not install global tools. On Apple Silicon the official release asset requires existing x86 compatibility support; it worked on the authoring host. Other platforms require deliberate toolchain selection as described in [TOOLCHAIN.md](TOOLCHAIN.md).

Install the project-local validation environment once (network required):

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install --cache-dir .cache/pip -r requirements-dev.lock
```

One validation command performs structural, shell-syntax, sample-syntax, behavioral and dependency checks:

```bash
.venv/bin/python scripts/validate.py
```

Additional checks with explicit scopes:

```bash
.venv/bin/python scripts/integration_check.py
.venv/bin/python scripts/browser_check.py --url http://127.0.0.1:8765/workshop/
python3 scripts/check_scope.py
```

The integration check binds a temporary loopback server, exercises real MCP HTTP requests and ADK discovery, then shuts down. No model, IAM or Daraja endpoint is called. **It passes functional assertions but logs upstream closed-stream teardown errors with the pinned MCP SDK; see VALIDATION.md.** Browser checks require the preview above and an existing Chrome installation plus the locked Playwright package. They do not install a browser. Scope checks compare all original repository file hashes captured before authoring.

## Edit the authoritative sources

- `labs/01-mpesa-mcp-server/codelab.md` and `labs/02-adk-payment-agent/codelab.md`: the two authoritative participant sources.
- `labs/*/sample-code/`: complete editable samples; their `requirements.txt` files specify direct pins and `requirements.lock` files record the resolved closures.
- `scripts/diagrams.py`: editable code-native SVG diagrams; builds regenerate `labs/*/assets/`.
- `site/index.html`, `site/workshop.css`, `site/codelab-overrides.css`, `site/codelab-navigation.js`: editable landing page and minimal renderer adaptations.
- `site/codelabs/` and `site/downloads/`: generated by `scripts/build.py`; do not edit by hand.

Build exports into `site/codelabs/` and packages sample-code downloads. It does not delete directories, change Git state, or write outside this folder. The metadata staging directory `.cache/export/` is generated and ignored. No watch dependency is needed: rerun build after an edit, then refresh the browser.

Participant exercises copy samples into ignored `.work/` directories to preserve authoring sources. The codelabs explain terminal choice, restart variables, expected outcomes, recovery and cleanup. A participant using only the website can download both complete sample archives.
